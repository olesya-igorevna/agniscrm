# agniscrm
Лёгкая self-hosted CRM для малого бизнеса

В этой ветке реализована задача **«Контакт: Go-структура и CRUD на моках»**.

## Запуск

Нужен Go 1.22 или новее. При первом запуске потребуется доступ к зависимостям.

```sh
go mod download
go run ./cmd/app
```

Адрес по умолчанию: `http://localhost:8080`.
`HTTP_ADDR` задаёт адрес прослушивания (например, `:8090`),
`GIN_MODE` — режим Gin (`debug`, `release`, `test`; по умолчанию `debug`).
База данных и `.env` для запуска не нужны. Данные хранятся в памяти и
сбрасываются при перезапуске. Авторизация на этом этапе отсутствует.

```sh
go fmt ./...
go vet ./...
go build ./...
go test -race ./...
```

## Методы контактов

| Метод | Путь | Успешный ответ |
| --- | --- | --- |
| GET | `/health` | 200, `{"status":"ok"}` |
| GET | `/api/v1/contacts` | 200, `{"items":[...],"total":3}` |
| GET | `/api/v1/contacts/{id}` | 200, карточка |
| POST | `/api/v1/contacts` | 201, созданная карточка |
| POST | `/api/v1/contacts/{id}/update` | 200, изменённая карточка |
| POST | `/api/v1/contacts/{id}/delete` | 200, `{"id":4,"deleted":true}` |

Изменение принимает **все редактируемые поля**, как создание: пропущенные
необязательные поля сбрасываются. Это полная замена, а не частичное обновление.
Серверные поля (`id`, даты) игнорируются в запросе. Список отсортирован по id.
Необязательные строки возвращаются как `""`, компания — как `null`, теги — как `[]`.

Пример создания:

```sh
curl -i http://localhost:8080/api/v1/contacts \
  -H 'Content-Type: application/json' \
  -d '{"first_name":"Арина","telegram":"arina_test","tags":["лид","лид"]}'

curl -i http://localhost:8080/api/v1/contacts/4

curl -i http://localhost:8080/api/v1/contacts/4/update \
  -H 'Content-Type: application/json' \
  -d '{"first_name":"Арина","phone":"+79990000000"}'

curl -i -X POST http://localhost:8080/api/v1/contacts/4/delete
```

Пример рассчитан на свежий запуск: первые три контакта — из приложения А ТЗ.
Полная подборка запросов и ошибок: [docs/contacts.http](docs/contacts.http).

## Проверки данных

Проверяются длины в символах (включая кириллицу), формат телефона/email/Telegram,
хотя бы один способ связи, до 10 тегов по 1–30 символов. Теги очищаются от
пробелов и повторов с сохранением порядка. Telegram получает префикс `@`.
Отсутствующий `owner_id` заменяется на 1; явный 0 отклоняется.

Ошибки возвращаются в виде `{"error":{"code":"...","message":"..."}}`.
При `validation_error` добавляется `details`: массив `{field,message}`.
Проверки связей возвращают 400, несуществующая карточка — 404,
удаление используемого контакта — 409, неверный метод — 405.

## Подключение к общему приложению

`RegisterContactRoutes` подключает методы контактов к общему Gin-router.
`usecase.ContactRepository` задаёт интерфейс хранилища.

Связи с другими сущностями пока представлены моковыми наборами id:
пользователи 1–3, компании 1–2, контакты 1–3 используются сделками.
При подключении остальных сущностей эти наборы нужно заменить проверками
общих карт пользователей, компаний, сделок и задач под тем же мьютексом.
Иначе новые связи не будут учитываться при удалении.

В приложении А ТЗ у Сергея Лебедева (id=3) отсутствует способ связи.
Начальная запись перенесена как в ТЗ; при её изменении требуется указать
хотя бы один способ связи. Даты начальных контактов устанавливаются при запуске.
